# AGENTS.md

DeepSeek Harness (DSH) plugin monorepo for **dsh-tool-web-enhanced-profile**: a code-free profile bundle that mounts two plugins and selects their `ctx.web` providers in the shared `web` row. The model keeps DSH's native `web_search`/`web_fetch` (tool-web); each plugin switches backends internally. When the operator turns on a row's Enhanced tools switch, that plugin also registers its own two model tools (`web_search_enhanced` + `list_web_search_providers`, `web_fetch_enhanced` + `list_web_fetch_providers`) so the Agent can pick a provider per call; model-facing "provider" means a connection. Targets DSH `>=0.2.1-rc.2 <0.3.0-0`, Node `^22.19.0 || >=24.0.0`, pnpm 12. Docs (Chinese): [architecture](docs/architecture.md) (structure, composition, runtime, security boundaries), [design](docs/design.md) (features and behaviour), [development](docs/development.md) (workflow, testing, release), [code structure](docs/code-structure.md) (as-built files and tests), [plan](docs/plan.md) (roadmap). `docs/orchestration-prompt.md`: the maintainer's multi-agent development brief (rewritten by the maintainer before each phase).

## Layout

- `packages/profile` – `dsh-tool-web-enhanced-profile`: `cordis.patch.yml` (writes both `web` fields, disables `web-search-deepseek`, inserts the plugin rows and the menu row), locale, icon. No code.
- `packages/search-enhanced` – `dsh-web-search-enhanced`: row `web-search-enhanced`, provider `search-enhanced`. Keeps only what is specific to search: catalog, the catalog binding of core wires (`src/search/adapters/`, `mapWire(<service>Search, searchSources)`) and the outcome→source/error mapping (`src/search/adapter-result.ts`, `sources.ts`), native backends, the `model` backend (`src/model/`: protocol requests and parsing, Session-model route derivation with DeepSeek handled in one place, cross-namespace read budgets, credentials and execution; the protocol table `MODEL_PROTOCOLS` sits in the catalog), freshness, `settings/resolve.ts`, the capability wiring in `src/host/` (`searchCapability`, connection status and listing facts, freshness codec), and `src/tools/` (enhanced tools: static definitions, argument checks, the multi-query merge copied from tool-web plus `capSources`, output and model-facing wording). Everything else comes from core; tests import core directly.
- `packages/fetch-enhanced` – `dsh-web-fetch-enhanced`: row `web-fetch-enhanced`, provider `fetch-enhanced`. Catalog `builtin:local` (default), `builtin:deepseek-fetch-api` and remote adapters Exa, Firecrawl, Tavily, Tinyfish; custom adapter connections. `src/local/` (allowlist rules, address policy, resolver around DSH's `HttpFetchProvider`), `src/backends/` (native), `src/remote/` (catalog binding of the core fetch wires, page→`WebFetchResult` mapping and failure wording in `page.ts`, transport constants, execution), `src/prompt.ts` (allowlist notice, with a subject parameter), `src/settings/`, `src/host/`, `src/tools/` (enhanced tools), `src/client/` (local allowlist and User-Agent editors, service notes).
- `packages/ui` – `dsh-tool-web-enhanced-ui`: row `tool-web-enhanced-ui`; empty Host face, browser face with the `webConnections` service, the single composer connection menu, the activation prompt and the bundle overview (route status, upgrade preflight). Plugins register sections into it through optional injection and keep their own `/setup-*` commands and row settings pages. It must never depend on a plugin row: it works with either, both, or neither plugin row enabled.
- `packages/core` – private, source-only shared code, inlined into each plugin at build time. `./shared` (ids including enhanced tool names, connection grammar including `isConnectionId`, settings document grammar, route, url, freshness, selection contract) must stay isomorphic (no Node, browser, or Host imports); `./host` holds the selection paradigm (`Capability`, `installCapability`, sessions, plans, Remote factory, route, credentials, bounded transport, `redaction` of request secrets in upstream text and diagnostics), the visibility controller (native tool masks; enhanced tool registration and masks), the explicit entry for enhanced tools (`EnhancedAccess` `run` / `list` / `ready`, contract types in `host/enhanced.ts`), conversation provider lists, the shared enhanced-tool parts (provider grammar check, rejection wording, hint insertion, listing text, canonical value schemas) and the remote backends' shared wire (MCP client, `AdapterWire` / `runAdapter` / `adapterTarget` / `mapWire`), plus per-service provider wires (`providers/<service>.ts`, named per capability: `exaSearch`, `exaFetch`, …; no provider table) with the search/fetch outcome vocabularies (`SearchInput` / `SearchOutcome`, `FetchInput` / `PageOutcome`); wires never word model-facing errors; `./client` holds the section contract (sections and route facts), `useObservable`, `ConnectionSelectionStore`, route/pairings/credential status, the `/setup-*` command factory and the catalog-driven settings page skeleton (services, endpoint trust, custom connections).
- `build/` – one tsdown factory for every plugin, platform module table, decorator and CSS Modules plugins.
- `scripts/` – workspace discovery/packing, package verification, clean.
- `e2e/` – isolated real-DSH suite: `harness/` (environment, host boot, `dsh web`, Playwright), `fixtures/`, `*.e2e.ts`.

## Commands

- `pnpm install`
- `pnpm run check` – typecheck, type-aware oxlint, build, vitest, verify:package. Must pass before you finish.
- `pnpm run test:e2e` – run when touching the profile patch, provider or enhanced tool registration and visibility, plugin-page metadata, browser faces, or the DSH baseline. Never touches the user's DSH home or running GUI. GUI specs need Chromium (`DSH_E2E_CHROMIUM`). Screenshots land in `.e2e/artifacts`.

Test environment quirks (see docs/development.md): browser tests start with `// @vitest-environment jsdom`; `primitivesStub()` in `vitest.config.ts` stubs only the implementation libraries the published `dsh-client-ui-primitives` imports without shipping (`clsx` gets a real minimal implementation); `zustand` and `immer` are root devDependencies because the published `dsh-client-store` imports them at runtime without declaring them. Do not remove either without checking the DSH packages.

Without network, set `npm_config_manage_package_manager_versions=false` and install with `pnpm install --offline`, or pnpm hangs.

Do not run state-changing git commands unless asked. Do not add dependencies without approval. `ipaddr.js` is an approved devDependency of fetch (same version as DSH `web-fetch-http`), inlined into its Host bundle.

## Invariants

- Identities (package names, row ids, provider ids, enhanced tool names) are defined once in `packages/core/src/shared/ids.ts`; the profile test asserts the YAML patch matches them. Naming follows DSH: a row id is its npm name without the `dsh-` prefix (`dsh-tool-web-enhanced-ui` → `tool-web-enhanced-ui`), and the Cordis plugin name equals the row id. Provider plugins are the `web-*-enhanced` family; product-level packages (profile, ui, private core) are `tool-web-enhanced-*`.
- The profile writes **both** `web` fields together; nothing else in this repo writes the `web` row. Backend switching never touches it.
- Each plugin registers exactly one `ctx.web` provider (its seat), plus its side's two enhanced tools, which core registers to the global tool layer only while the `web` row is confirmed to route to this plugin and the row's `enhancedTools` switch is on (all presets, minimal included, and base get them). There is no tools row package. New behaviour goes into the planner (which backend), a backend (how), or the explicit entry, never a second provider registration.
- Plugins ship self-contained host bundles: runtime imports only Node built-ins and `@deepseek-ai/*` (including the `@deepseek-ai/dsh-tool-web` peer, whose formatters and meta functions the enhanced tools reuse); no `dependencies`. `verify-packages` enforces it.
- search and fetch never import each other in `src`; shared code goes to core; core holds no module-level state. Composition tests may import another package's `src` to exercise the real seam (for example ui × search).
- `available()` does no I/O. Credentialed requests use `redirect: 'error'`. Keys live in DSH Credentials (settings store `credentialRef`); only `native` backends and a `model` connection following a Session route resolve them by DSH's own route rule, which reads the launch environment when the Credentials service is absent; for the backends this repo implements (adapters and `model`), an API key with characters other than printable ASCII and spaces is refused before any request; `native` backends keep DSH's own key handling. Keyless never reads, sends, or falls back to a key, and always uses the catalog endpoint (core `adapterTarget`). A DeepSeek account token goes only through `native` backends (DSH's providers prefer it when the request route is `deepseek-account` and otherwise use the API key, as natively) and, as the one addition, a search `model` connection following a `deepseek-account` Session route: obtained only when this request's resolved route is `deepseek-account`, sent only to the session endpoint, checked for printable ASCII before sending, never replaced by an API key. No automatic retry or fallback; switching to another backend after a failure is left to the Agent (the enhanced tools).
- search and fetch share one selection paradigm: operator-defined connections in the row settings, a per-Session selection frozen per model request step, `null` = off (Seat error + `agent.ctx.tools.restrict`). Differences between the two are catalog data and capability parameters, never a second mechanism. Only "which connection" (plus session options) is frozen; whether it is still selectable (exists, enabled) is judged per call by one rule (core `isSelectable`), and the execution target is rebuilt from current settings on every call (a `model` connection's route too: never frozen in the plan). The native tool mask is installed only while the `web` row is confirmed to route to this plugin.
- Enhanced tools: when in doubt, hide. Definitions are registered only on a confirmed route with the switch on and valid settings, and masked for an Agent whose conversation has no provider list, whose Session is off, or whose selection is unread or failed (the opposite of the native mask, which stays off when unsure). Register and mask in one synchronous commit (the pair registers atomically: a failed second registration rolls back the first, and a later recompute retries); async reads commit only for the current registration generation and per-Agent operation version, through one commit point, never via timers; the enhanced group lives in the `tools` + `agents` injection scope and unloads in one effect: invalidate reads → unregister → lift masks. A conversation's provider list is recorded once, when a new top-level conversation creates its first Agent (new = public header fields only: no `parentSession`, not `isSeeded`, `firstLiveSeq` and `firstLifecycleSeq` both 0): the selectable ids if the tools are offered, otherwise an empty record (empty = no list), so it is never backfilled. Children copy the parent's record, restored conversations read it; records are only added, never rewritten or migrated. The model's `provider` is untrusted input: it must pass the connection id grammar and can only resolve to a connection in that list that still exists (disabled members stay usable, removed ones are `removed`). Explicit calls never write the Session selection or model pairings, refuse frozen `off` / failed plans, run as `call.agent` inside `agents.withInitiator`, and use the same execution layer as the seat (current-settings target, credentials, keyless, endpoint trust, deadlines, redaction, upstream explanations, cancellation). `list` turns any `describe` / `listing` exception into the fixed `WEB_PROVIDER_ERROR`; `ready` and the `ReadyProviders` of `unknown` / `removed` rejections never throw and are `unread` when readiness cannot be read, so the wording never claims "none ready" unread. Text the enhanced tools add holds only fixed wording and list ids. Tool definitions are static: available providers never enter a schema or description.
- Both rows use one settings document grammar (core `shared/settings.ts`: `version`, `defaultConnection`, `showSelector`, `enhancedTools`, `defaults`, `connections`), validated by one pure function shared by Host and browser (each plugin's `resolveSettings` over core's `resolveDocument`). Remote service backends are off by default: a builtin connection's `disabled` defaults to its catalog `optIn`, custom connections default to enabled, and the settings page writes the switch as a layer-aware sparse override; the Host never rewrites a document. A custom endpoint, or a `url` option such as a native `baseURL` that differs from the catalog endpoint, needs `trustedEndpoint: true`. Unsafe keys (`__proto__`, `constructor`, `prototype`) are rejected; text and connection counts are bounded. 0.1.x settings are not read or migrated: the Host rejects them (the plugin still activates; calls fail with `WEB_PROVIDER_CONFIGURED_UNAVAILABLE`), the settings page names the fields and offers Reset. Future versions migrate through the pure N→N+1 table in `migrateDocument` (empty today).
- fetch: only the `local` connection (DSH's `HttpFetchProvider` plus our injected resolver) checks target addresses; an empty allowlist equals native public-only, and proxied hostnames are resolved by the proxy, as upstream does. Remote backends follow DSH's own design: the service owns target access policy; we reject redirects of the API request, keep cancellation, and state in the UI who receives the URL. Remote results are text; without a reported target status they are 200 for the requested URL (compatibility mapping), and only a status the service reports becomes a non-2xx result. `native` backends instantiate DSH's exported provider classes and keep their behaviour; only their error messages are restated. Our own egress uses global `fetch` only.
- Model-facing errors are `WebError` with an existing `WEB_*` code and a short actionable English message of our own. After it they may carry the upstream's own explanation as `\n\n<label> responded (untrusted): <text>` (HTTP error bodies, per-URL failures, API error envelopes, MCP tool and JSON-RPC errors; `native` carries only the first paragraph of DSH's error, never DSH's settings guidance): bounded to 2000 characters. This request's API key or account token is kept out of what the model sees (core `redaction.ts`; known gap in [design](docs/design.md#已知限制): DSH's own native parse errors may quote a credential fragment shorter than 8 characters): in error text (error bodies, MCP errors, DSH's native message) a detected credential, whole or an 8-character fragment, withholds the whole explanation, replaced by "<label>'s response was withheld because it contained this request's credential."; in successful bodies (including per-URL failures and search envelopes inside them, model answers, fetched pages) it becomes `[redacted]`. Missing keys, cancellation and unexpected exceptions use fixed wording; any exception from a credential or account resolver (even a `WebError` with a plausible code) counts as unexpected, and only real cancellation of the call's signal becomes `WEB_ABORTED`. Enhanced tools insert their switch-provider hint at the end of the first paragraph, before any untrusted explanation, and keep the execution layer's wording (including "connection"). All diagnostics reach the Host log only as redacted copies without the original cause or stack. Remote services (`<ns>/*`) pass contract errors through (invalid row settings are `<ns>/invalid-settings`) and turn anything else into `gateway/internal` with a fixed message; the original goes only to the Host log. UI text goes through locale dictionaries (zh and en, same keys) in each package's `src/client/locales.ts`; `locale/*.json` holds only the Plugins-page `meta`.

## Conventions

- Readable code over dense one-liners; small focused modules; JSDoc on exports only when it adds information.
- No over-defensive code: no error-swallowing try/catch, no shape-sniffing of private DSH internals, no `?.`/`??` piles for values that are always present, no timing-based correctness.
- Discriminated unions over bags of optional fields.
- Tests exercise behaviour at seams (real `WebRuntime`, real include patch algorithm, local HTTP servers, the real DSH in e2e). Mock only the network and the clock. Every bug fix gets a failing-first test.
- Keep docs in sync and describe only the current state (git keeps the history): behaviour changes update docs/design.md, structural changes docs/architecture.md, file and test changes docs/code-structure.md, workflow changes docs/development.md, roadmap changes docs/plan.md; plus the affected package README and CHANGELOG.md.
